# Slack standup generator

Builds a daily standup from your GitHub, Jira and Confluence activity plus a
personal notes file, and optionally posts it to Slack.

This started as a Go port of an earlier Python script. The tests compare the
Slack message, AI prompts and summaries against golden files that were first
produced by that script, so the output matches the original.

## Quick start

```bash
go build -o standup ./cmd/standup

./standup --dry-run     # first run writes standup_config.toml; edit it, then run again
./standup --post        # generate and post to Slack
```

Sources whose token is not set are skipped with a warning, so the tool works
with any subset of GitHub, Jira, Confluence and notes.

## Usage

| Flag | Effect |
|---|---|
| `--dry-run` | Fetch data and print the message, but never post. Takes precedence over `--post`. |
| `--post` | Post to Slack. Exits non-zero if posting fails. |
| `--debug` | Log debug detail, including the Slack blocks. |
| `--config PATH` | Config file (default `standup_config.toml`). |
| `--channel NAME` | Slack channel or user (such as `#team` or `@name`), overriding the config file. |

Logs go to stderr and the standup itself goes to stdout.

On a Monday the report covers everything since Friday. On other days it covers
since the previous weekday, and Saturday and Sunday look back to Friday.

## Environment variables

| Variable | Used for |
|---|---|
| `GITHUB_TOKEN` | GitHub commits, pull requests and reviews |
| `JIRA_TOKEN` | Jira API token (paired with `jira.username`) |
| `CONFLUENCE_TOKEN` | Confluence API token (paired with `confluence.username`) |
| `SLACK_WEBHOOK_URL` | Posting with `--post` |
| `ANTHROPIC_API_KEY` | AI summaries when `provider = "anthropic"` |
| `OPENAI_API_KEY` | AI summaries when `provider = "openai"` |

The Slack webhook URL is a secret. It is never included in error messages or logs.

## Configuration

The config is TOML. The first run writes this file with placeholder values:

```toml
[github]
username = "your-username"
repos = ["org/repo1", "org/repo2"]

[jira]
base_url = "https://your-org.atlassian.net"
username = "your-email@company.com"

[confluence]
base_url = "https://your-org.atlassian.net"
username = "your-email@company.com"

[notes]
file_path = "./daily_notes.md"

[slack]
channel = "#standup"
username = "Standup Bot"
icon_emoji = ":robot_face:"

[ai_summary]
enabled = true
provider = "none"             # "anthropic", "openai" or "none"
model = "claude-haiku-5-5"    # must suit the provider; empty uses the provider's default
prompt_style = "professional" # "professional", "casual" or "detailed"
```

Notes on the AI summary:

- With `provider = "none"`, or when the provider's key is missing, the summary
  is a simple count such as `Completed: 12 commits, 2 PRs.`
- If the provider call fails, the same simple summary is used and the error is logged.
- With `enabled = false`, the message shows the detailed breakdown by source instead.

The config also has `include_*` and `project_keys` settings (inherited from
the original script) that are currently ignored.

## Notes file

Date headers are `##` lines containing `YYYY-MM-DD`. Bullets can use `-`, `*`
or `+`.

```markdown
## 2025-03-10
### Completed
- Fixed the login bug
### Plan
- Review the release PR
```

- Completed items are included for the last workday and later.
- The plan is taken from today's section only.
- Bullets under a date with no `###` subsection count as completed.

A missing notes file is not an error.

## Development

```bash
go vet ./...
go test ./...              # add -race for the race detector, -count=1 to skip the cache
```

### Layout

```
cmd/standup/            flags and wiring
internal/
  activity/             data types shared between packages
  config/               TOML config and environment secrets
  workday/              last-workday logic
  notes/                notes file parser
  source/{github,jira,confluence}/   API clients
  httpx/                JSON requests, Link-header paging, status errors
  summary/              prompts, OpenAI and Anthropic providers, simple summary
  render/               Slack blocks and plain-text message
  slack/                webhook poster
  standup/              concurrent gathering and posting with fallback
```

Each source client returns what it managed to collect together with an error,
so one failing repository or search does not hide the rest.

### Golden files

`internal/render/testdata/` holds JSON fixtures (`<name>.json`) and the output
expected for each: the plain-text message, Slack blocks, AI prompts for each
style, and the simple summary. The render and summary tests compare against
these files. The originals were generated by the Python script this tool was
ported from, and the Go code reproduces them exactly.

When you change the output on purpose, rewrite the golden files from the
current code and review the diff:

```bash
UPDATE_GOLDEN=1 go test ./internal/render ./internal/summary
git diff internal/render/testdata
```

The golden files only catch changes in behaviour, so check the diff by eye
before keeping it.

To add a case, create a new `<name>.json` fixture in that directory. Copy an
existing one to see the fields: `now`, `github`, `jira` and `confluence` (use
`null` for an unavailable source), `notes`, and `ai_summary`. Then run the
command above, and the tests pick it up automatically.

## Differences from the original Python script

- Branch, commit, pull request, Jira and Confluence listings follow pagination
  instead of stopping at the first 50 or 100 results. Hitting the safety limit
  of 20 pages is reported as an error.
- Pull requests are listed by last update, so one opened earlier but merged
  since the last workday is counted as merged.
- The Slack channel always comes from the config (or `--channel`) rather than
  being fixed in the code.
- The sources are fetched concurrently, and every request has a 30 second timeout.
- Confluence no longer runs its extra debugging query.
- `--post` exits non-zero when posting fails.
